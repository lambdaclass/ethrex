# EIP-8504: Proof Frames for leanSPHINCS Signatures

> **Spec target:** draft EIP-8504 as proposed in ethereum/EIPs#12672. The draft specifies the proof
> frame, its dependencies, the leanSPHINCS scheme and the mempool rules. It does not yet specify
> how signatures travel in a block, how they are priced, or the network messages that carry them.
> ethrex decides those three here; they are listed under [Design decisions](#design-decisions) and
> are provisional until the EIP specifies them.

Implementation notes for EIP-8504 in ethrex. It builds on [EIP-8141](./eip-8141.md) frame
transactions and is part of `Fork::Hegota`: it activates with it. From `Fork::LStar` a block
carries one proof in place of the witnesses, as EIP-8288 specifies it; see
[LStar: one proof for the block](#lstar-one-proof-for-the-block).

## Overview

EIP-8504 gives frame transactions native leanSPHINCS signatures whose bytes are not part of the
transaction.

- **Declare.** A transaction carries a **proof frame**, a frame with `mode = 4`. Its data is a list
  of 96-byte triples `(scheme, data_hash, verification_key_hash)`. The only scheme is leanSPHINCS,
  `0x10`. A zero `data_hash` stands for the transaction's own signature hash. The frame executes no
  code: it consumes its whole execution limit, 3,000 gas per triple, and yields a successful
  receipt.
- **Read.** An account's validation code reads the triples with EIP-8141's `FRAMEPARAM` and
  `FRAMEDATACOPY`, and approves when one of them names its key and its message. The EIP adds no
  instruction.
- **Satisfy.** Each distinct triple of a transaction is a **dependency**. A **witness**, a
  7,740-byte signature, satisfies it. Witnesses travel beside the transaction: in a **wrapper**
  while the transaction is pending, and in the block's `dependency_witnesses` list once it is
  included. Every node verifies them natively, before the block executes.

## How to use it

1. **Schedule Hegotá.** EIP-8504 is part of it, so the chain config needs nothing else:

   ```json
   "config": { "hegotaTime": 0 }
   ```

2. **Create accounts controlled by leanSPHINCS keys.** `leansphincs_sender` derives keys from a
   seed and prints the genesis entries of their accounts, each running validation code for its
   key. Merge the output into the genesis `alloc`.

   ```sh
   cargo run --release --manifest-path tooling/Cargo.toml -p leansphincs_sender -- \
     alloc --accounts 4 > alloc.json
   ```

3. **Run the node.** To exchange dependency transactions with peers the node needs
   `--blob-sampling`, since they travel over eth/73 (see [Networking](#networking)). A single node
   needs no flag:

   ```sh
   cargo run --release --bin ethrex -- --network genesis.json --dev --metrics
   ```

4. **Send transactions.** The same tool signs `[VERIFY, PROOF, SENDER]` transactions and submits
   each one with its signature through `eth_sendRawTransaction`:

   ```sh
   cargo run --release --manifest-path tooling/Cargo.toml -p leansphincs_sender -- \
     send --accounts 4 --rpc-url http://localhost:8545 --rate 2 --count 8
   ```

   ```text
   Sending from 4 accounts on chain 9 at 2 tx/s
   sent 0x9e97…aa7e from 0xbd6f…ae50 nonce 0 (8032 bytes)
   ...
   Done in 3.6s: 8 sent, 0 sent again, 4 seen included, 0 rejected
   ```

5. **Read the result.** The receipt has `status 0x1` and uses about 519,000 gas, of which 495,360
   pay for the witness. `eth_getBlockByNumber` with full transactions lists the block's witnesses:

   ```json
   {
     "dependencyWitnessesHash": "0x74ef…51d3",
     "dependencyWitnesses": ["0x…", "0x…"],
     "transactions": [{ "type": "0x6", "frames": [{ "mode": "0x1" }, { "mode": "0x4" }, { "mode": "0x2" }] }]
   }
   ```

To submit a transaction without the tool, send the type byte followed by the transaction and its
witnesses, one witness for each entry of `dependencies(tx)` in that order:

```text
0x06 || rlp([tx_payload_body, witnesses])
0x06 || rlp([tx_payload_body, wrapper_version, blobs, commitments, cell_proofs, witnesses])   with blobs
```

## Architecture

```text
eth_sendRawTransaction ──┐                       ┌── NewProofWrapperHashes ──► peers
                         ▼                       │
   ProofWrapper ──► admission ──► mempool ───────┤
   (tx + witnesses)  1 size       tx pool        └── payload builder
                     2 static     + dependency_witnesses_pool      │
                     3 count                                       ▼
                     4 deps match                     block body: transactions,
                     5 satisfies                      dependency_witnesses
                     6 EIP-8141 acceptance            header: dependency_witnesses_hash
                                                                   │
            peers ──► GetProofWrappers / ProofWrappers             ▼
                                                      import: validate_dependency_witnesses
                                                      (count, order, satisfies) then execute
```

A dependency transaction is handled in three forms. The **submitted form** is what a user sends.
The **wrapper**, `rlp([[tx], 0, [deps, witnesses]])`, is what the pool keeps and peers exchange;
`deps` restates the transaction's dependencies so a receiver can check them before verifying
anything. In a **block** the transaction is an ordinary type-6 transaction and its witnesses sit in
the body's list, where a dependency shared by several transactions has a single witness.

## Activation

EIP-8504 is part of Hegotá and has no activation of its own: everything here is gated on
`ChainConfig::is_hegota_activated(timestamp)`. Before Hegotá there are no frame transactions, and
blocks have neither the witness list nor its commitment.

A chain that starts in Hegotá has the commitment in its genesis block. A genesis generator that
does not know the EIP computes that block without it, so on a network whose consensus genesis
comes from such a generator Hegotá has to be scheduled after genesis.

The consensus layer changes at the same instant. Its execution payload has the witness list from
Hegotá's epoch, `HEZE_FORK_EPOCH` in its config, and not before, so the consensus client must be
told that epoch. `fixtures/networks/pq-el-devnet-0.yaml` keeps `frames_enabled` off for that
reason: with it on, the genesis generator leaves the epoch out of the consensus config.

Fixtures generated for Hegotá without this EIP do not apply to this branch: their Hegotá blocks
have no commitment in the header, which the header rules reject.

## Block

- The body's fourth item is `dependency_witnesses`: a list of byte strings with one witness for
  each entry of `block_dependencies(block)`, the block's deduplicated dependencies in ascending
  order of `(scheme, data_hash, verification_key_hash)`.
- The header's `dependency_witnesses_hash` is the Keccak-256 hash of that list's RLP encoding. It
  sits between `slot_number` and `burned_fees`.
- Both are present, possibly for an empty list, from activation until LStar, and absent before
  and after.
- `validate_dependency_witnesses` runs on every import path before execution. It rejects a block
  whose list has a different number of items than its dependencies, or in which a witness does not
  satisfy its dependency.

The Engine API carries the list as `dependencyWitnesses`, an array of hex strings, in the execution
payload of `engine_newPayloadV5` and `engine_getPayloadV6` and in the payload bodies responses. The
node derives the header's commitment from it. An absent field is the empty list once the EIP is
active; before that, an absent or empty field means no list.

## Gas

A proof frame's `limits.execution` must be exactly 3,000 gas per triple, and the frame consumes all
of it. Until LStar each dependency of a transaction also adds `LEANSPHINCS_WITNESS_GAS`, 495,360
gas, to the transaction's mandatory gas: the 7,740 bytes of a signature at the calldata floor of 64
gas per byte. A triple declared more than once is paid once. A dependency shared by two
transactions is paid by both, while the block carries one witness.

## LStar: one proof for the block

From `Fork::LStar` (`lstarTime` in the chain config) a block follows the block rules of
[EIP-8288](https://eips.ethereum.org/EIPS/eip-8288): its builder aggregates the witnesses of the
block's dependencies into one **dependency proof**, and the block carries that proof in place of
the witnesses. Nothing changes for a pending transaction: it is submitted with its witnesses, the
pool verifies each one, and it travels in its wrapper over eth/73. Accounts and their validation
code do not change either, so an account keeps authorizing with the same key across the fork, and
a transaction signed before LStar is valid in a block after it.

```json
"config": { "hegotaTime": 0, "lstarTime": 1767225600 }
```

- **Fields.** The body has no `dependency_witnesses` and the header no
  `dependency_witnesses_hash`. The body's last item is `dependency_proof`, a byte string, empty
  when the block has no dependencies. The header has `dependency_proof_hash`, the Keccak-256 hash
  of the proof, and `block_deps_hash`, the Keccak-256 hash of `data_hash || verification_key_hash`
  of each entry of `block_dependencies(block)` in order. The two follow `burned_fees`. No root of
  the body covers the proof: the header's hash of it is the commitment.
- **Validity.** `validate_dependency_proof` runs where `validate_dependency_witnesses` runs before
  LStar, on every import path and before execution. In EIP-8288's order: `block_deps_hash` is the
  digest of the block's dependencies; the proof has at most `MAX_DEPENDENCY_PROOF_BYTES`, 1 MiB;
  `dependency_proof_hash` is the hash of the proof; and the proof is empty when the block has no
  dependencies, or else `leansphincs_aggregate_verify` accepts it for exactly the block's
  dependencies, each read as a `(public key, message)` claim. A block that still carries a witness
  list, and a Hegota block that carries a proof, are invalid.
- **Gas.** `LEANSPHINCS_WITNESS_GAS` is no longer charged. Each triple of each proof frame adds
  `LEANSTARK_VERIFICATION_GAS`, 30,000 gas, to the transaction's mandatory gas, a triple declared
  twice being paid twice. The frame's own 3,000 gas per triple do not change. The
  `[VERIFY, PROOF, SENDER]` transaction that uses 519,153 gas in a Hegota block uses 53,793 in
  an LStar block; in both it is bound by the calldata floor.
- **Builder.** The builder takes the witnesses from the pool as it adds transactions, as before.
  The proof is made by `PayloadBuildResult::with_dependency_proof`, once, for the payload that is
  handed out: `build_payload_loop` rebuilds the payload as transactions arrive and proves only the
  one it ends with, on a blocking thread. Proving takes from a tenth of a second to several
  seconds; the proof of four signatures has about 230 kB, where the four witnesses have 31 kB. The
  prover is prepared when the first LStar payload build starts, so that the first proof does not
  wait for it. A proof that cannot be made fails the build; the block never falls back to
  witnesses.
- **Engine API.** The payload carries the proof as `dependencyProof`, a hex string, where a
  Hegota payload has `dependencyWitnesses`, in `engine_newPayloadV5`, `engine_getPayloadV6` and the
  payload bodies responses. The node derives the two header fields, so a payload whose proof or
  transactions do not match its block hash is `INVALID`, as is one whose proof is over the size
  bound, is not empty without dependencies or does not hold. An absent field is the empty proof
  from LStar; before, an absent or empty field means no proof.

The gas functions of a frame transaction take the fork of the block (`mandatory_gas_at`,
`max_gas_at`, `fee_budget_at`, `Transaction::gas_limit_at`), because a frame transaction has no gas
limit field: its `max_gas` follows from its intrinsic gas, which differs between the two forks.
The functions without a fork give the values of Hegota.

## Mempool

Admission follows the EIP's order, cheapest check first:

1. The wrapper is no larger than the largest transaction plus a triple and a signature for each
   dependency the node verifies.
2. The transaction satisfies the static constraints.
3. It has at least one dependency and at most `MAX_SIGS_PER_TX`, 16 by default, set with
   `--mempool.max-sigs-per-tx`.
4. The wrapper states exactly the transaction's dependencies, with one witness for each.
5. Every witness satisfies its dependency.
6. The transaction passes EIP-8141's acceptance algorithm.

Proof frames are skipped when the transaction's frames are matched against the recognized
validation prefixes and when checking that an expiry frame comes first, and their gas does not
count toward `MAX_VERIFY_GAS`. Witnesses are verified once: the revalidation after each block does
not repeat it. A transaction with proof frames that arrives without witnesses is rejected, and an
additional wrapper for a pooled transaction is ignored.

## Networking

A dependency transaction is never sent in `Transactions` or `PooledTransactions`, and never
announced in `NewPooledTransactionHashes`. It travels in its wrapper over a provisional **eth/73**,
which is eth/72 plus three messages:

| Message | Code | Content |
|---|---|---|
| `NewProofWrapperHashes` | `0x16` | `[[wrapper-hash, tx-hash, length], ...]` |
| `GetProofWrappers` | `0x17` | `[request-id, [wrapper-hash, ...]]` |
| `ProofWrappers` | `0x18` | `[request-id, [wrapper, ...]]` |

A node announces the wrappers it has admitted and sends one only on request. The receiver skips a
wrapper whose transaction it already holds or whose length it would never admit, fetches each
transaction from one peer at a time, and never asks the same peer twice for the same transaction.
A peer is disconnected when it sends a wrapper that was not requested, that is for another
transaction than it announced, or that fails checks 4 or 5, and when it keeps announcing wrappers
it does not deliver.

ethrex offers eth/72 only with `--blob-sampling`, because that version elides blobs from pooled
transactions. eth/73 includes eth/72, so it is offered under the same condition.

## Design decisions

The first five are not specified by the draft EIP and are ethrex's provisional choices.

- **Witnesses are a body list with a header commitment.** The alternative, placing them outside
  the block, would leave the execution block hash unable to commit to data every node needs to
  validate the block.
- **The commitment precedes `burned_fees`.** Trailing optional header fields decode by position
  and type, and a 32-byte hash before an integer keeps every combination unambiguous.
- **Witness bytes cost the calldata floor.** They occupy block space like calldata, and the floor
  is the price at which calldata cannot be undercut. With 495,360 gas per dependency, the
  transaction gas cap limits a transaction to about 33 distinct dependencies.
- **Three network messages on a new `eth` version.** The transaction hash in the announcement
  lets a node skip a wrapper for a transaction it already has, since a transaction can have
  several valid wrappers.
- **No separate byte cap for pooled witnesses.** The pool's transaction count bounds them at 16
  signatures each, the same order as the existing bound of one maximum-size transaction each.
- **The verifier is native-only.** `leansphincs_verify` lives behind the `leansphincs` feature of
  `ethrex-crypto`, and the block check lives in `ethrex-blockchain`, so zkVM guest programs do not
  link it. Stateless execution cannot verify witnesses yet, so it rejects any block that has
  transactions with proof frames instead of executing them unchecked.
- **Hash-only blocks omit the witnesses.** `eth_getBlockByNumber` without full transactions
  returns the commitment only; at 7,740 bytes each the witnesses would dominate the response.
- **A block built from an explicit transaction list cannot include a dependency transaction.**
  `testing_buildBlockV1` carries no witnesses.

EIP-8288 leaves these open for the LStar block, and ethrex decides them provisionally:

- **`DEPS_HASH` is Keccak-256.** The EIP ties it to the hash the aggregation circuit uses for its
  claims, which the proof system behind `leansphincs_aggregate_verify` does not expose: the proof
  is verified against the list of claims itself, and `block_deps_hash` is checked beside it.
- **The proof is stored and synced with the block body.** The EIP keeps the proof out of the
  block body and does not say how a syncing node gets it. Here it is the last item of the body in
  storage and in `BlockBodies`, and the body is checked against the header's commitment when it
  is downloaded. It is not part of the RLP block that the size limit of EIP-7934 covers, nor of
  the block size `eth_getBlockByNumber` reports.
- **The two hashes follow `burned_fees`.** A header never has them together with
  `dependency_witnesses_hash`, and the integer between them keeps the header's trailing fields
  decodable by position and type.
- **A chain that starts in LStar has no proof in its genesis block.** The genesis header has no
  `burned_fees`, without which the two hashes could not be told apart from the Hegota commitment.
- **The proof is made when the payload is requested.** `engine_getPayload` waits for it. Proving
  each rebuild would spend seconds of proving on payloads nobody asks for.
- **The proof gas replaces the witness gas.** EIP-8288 defines the first and knows nothing of
  the second; a block that carries no witnesses charges for none.

## Testing

```sh
cargo test --release -p ethrex-test --features rocksdb -- eip8504 eip8288 eth73 proof_frame
cargo test --release -p ethrex-common --lib -- wrapper dependencies dependency_proof deps_hash proof_frame
cargo test --release -p ethrex-blockchain --lib -- dependency_witnesses dependency_proof
cargo test --release -p ethrex-crypto --features leansphincs-aggregation,c-kzg --lib -- leansphincs
cargo test --release --manifest-path tooling/Cargo.toml -p leansphincs_sender
```

The end-to-end tests sign with real leanSPHINCS keys: they take a transaction from submission to a
built block and its import on both paths, and reject the block with a tampered or missing witness.
`crates/common/crypto/testdata/leansphincs_verify.txt` holds verification vectors from the
executable specification the EIP pins.

The tests of the LStar block build it with the payload builder, real signatures and a real proof,
and import it on both paths and through the Engine API. They reject a proof that misses a
dependency, that is for another message or key, that is damaged, empty, over the size bound or
present without dependencies, a header whose commitments do not match, and a block with the
wrong fork's fields. One chain crosses the fork with the same account authorizing on both sides.
