# EIP-7906: Transaction Assertions (POST_TX frames)

> **Spec target:** ethereum/EIPs `EIPS/eip-7906.md` (Draft, Standards Track: Core; requires EIP-8141), at commit **`0af4e0044d89419afb2a1ef960db9007218daecb`** ("Add POST_TX enforcement to security considerations", 2026-07-28).
>
> Stamp a COMMIT, never a date. This file previously read "master on 2026-06-24"; four revisions landed after that (2026-06-29 TXDIFF EIP-2929 pricing, 07-06 POST_TX revert behaviour, 07-09 per-address TXDIFF views + account change flags, 07-28 POST_TX enforcement), and the implementation silently drifted out of compliance on three of them.

Implementation notes for EIP-7906 in ethrex. Builds on EIP-8141 frame transactions; activates under `Fork::Hegota`.

## Overview

EIP-7906 lets a frame transaction append **assertion frames** that inspect the whole transaction's effects after the body has executed and **revert the execution body** if an invariant is violated (e.g. "this tx made no hidden ERC-20 approval"). It adds:

- A new frame mode **POST_TX** (`mode = 3`): a trailing-suffix frame, run read-only (STATICCALL, caller = ENTRY_POINT) after the tx body. Its revert reverts the body but does **not** invalidate the transaction: the tx is included with a `status = 0` receipt, and the validation prefix — the APPROVE gas payment, a deploy frame's account creation — stays committed with the payer fully charged.
- Three introspection opcodes — **TXTRACE**, **EVENTDATACOPY**, **TXDIFF** — that read the transaction-scoped state/event diff and gas context. They are valid **only inside a POST_TX frame's call subtree**; anywhere else they exceptional-halt.

## Frame-mode namespace (Hegota)

| Mode | Value | EIP |
|------|-------|-----|
| DEFAULT | 0 | 8141 |
| VERIFY | 1 | 8141 |
| SENDER | 2 | 8141 |
| **POST_TX** | **3** | **7906** |
| DEP_VERIFY | 4 | 8288 (deferred) |

`validate_static_constraints` admits modes `0..=3` (`frame.mode >= 4` is rejected). When EIP-8288 resumes, relax to `>= 5`.

## Implemented (this branch)

| Piece | Detail |
|-------|--------|
| `FrameMode::PostTx = 3` | `from_u8(3)`, `From<FrameMode> for u8`, dispatch in the frame loop → `(caller = entry_point, static = true)`; rejected in the validation-prefix simulation (POST_TX is body, never prefix). |
| Trailing-suffix rule | Static check: once any frame is POST_TX, every later frame must be POST_TX (`"POST_TX frames must form a contiguous trailing suffix"`). |
| Body revert (partial) | A reverted POST_TX frame sets `post_tx_reverted` (both the atomic-batch-revert and non-batch-revert sites in `vm.rs`), overriding atomic-batch unrolling. Distinct from a reverted VERIFY frame, which still sets `tx_invalid`. After the frame loop the body is rewound: `body_backup` (originals for every frame past the prefix) restores state, a substate checkpoint opened at body entry drops the body's logs / self-destructs / EIP-3529 refunds, `all_logs` truncates to the prefix mark, and the body's EIP-8037 state gas is dropped. Execution then falls through to the normal gas finalization, so the payer is charged and the tx reports `status = 0`. |
| Prefix/body boundary | The prefix REGION is frames `0..=max(ValidationPrefix::frame_indices)` — the same range `simulate_validation_prefix` runs, so interleaved expiry-verifier frames (absent from `frame_indices`) count as prefix. An unrecognized prefix shape cannot enter the mempool; if one reaches execution it has no prefix to protect, so every frame is body. |
| Per-frame receipt statuses | Left as each frame's own outcome: a body frame that succeeded before the assertion fired still reports success, and only the POST_TX frame reports failure. The top-level status is derived from all frames, so the tx is still `status = 0`; the upside is that the receipt names *which* assertion fired. |
| Opcode gating | `require_post_tx_frame(vm)` gates TXTRACE / EVENTDATACOPY / TXDIFF: halts (`InvalidOpcode`) unless the enclosing tx frame's mode is POST_TX. Holds for nested calls in the POST_TX subtree (`current_frame_index` tracks the enclosing tx frame). |
| `TXTRACE` | `0xB6`. Stack `[in2, param]` (in2 on top). Reads the tx-scoped diff: balance/slot/code-deployment changes (counts + indexed fields), ordered event fields, gas pre-charge (`0x14`) and gas payer (`0x15`). Gas 100. |
| `EVENTDATACOPY` | `0xB7`. Stack `[event_index, memOff, dataOff, length]`. Copies an emitted event's data into memory (past-the-end reads halt; no zero-fill). Gas mirrors CALLDATACOPY. |
| `TXDIFF` | `0xB8`. Keyed lookup; stack `[param, address, in3]` (param on top, then address, then `in3`). **Keyed params:** 0x00 slot_before / 0x01 slot_after / 0x02 balance_before / 0x03 balance_after / 0x04 codehash_before / 0x05 codehash_after — `in3` is the slot key for the slot params and must be zero for the scalar ones. "before" reads the tx prestate (`initial_accounts_state`), "after" the live post-body state (`current_accounts_state`); a key the tx never modified reads the live value both ways; an undeployed account's codehash_before is the empty-Keccak hash. **Per-address views:** 0x06 `address_slots_count` / 0x07 local slot index → global `slots_changed` index / 0x08 `address_events_count` / 0x09 local event index → global `events_count` index. A local index ≥ the view's count exceptional-halts. **0x0A `account_change_flags`:** `0b0001` nonce / `0b0010` balance / `0b0100` any storage slot / `0b1000` codehash, each vs the tx prestate; answered from the diff caches alone, so an untouched address returns 0 without a live read. **Gas:** 0x00-0x05 are priced through the EIP-2929 access lists (cold/warm SLOAD for the slot params, cold/warm account access for the rest) and warm the slot/address; 0x06-0x0A are a flat `TXTRACE_GAS_COST` and leave the lists untouched. |

## Divergences from the draft spec

1. **TXDIFF's EIP-2929 costs are fork-aware, not the spec's literal integers.** The spec writes the state-reading params' cost as `COLD_SLOAD_COST (2100)`, `COLD_ACCOUNT_ACCESS_COST (2600)` and `WARM_STORAGE_READ_COST (100)`. ethrex calls the fork-aware `gas_cost::sload` / `gas_cost::balance` instead, because **EIP-8038 reprices cold state access at Amsterdam and Hegota is post-Amsterdam** — charging the hardcoded 2100 would make TXDIFF a strictly cheaper cold-state read than SLOAD on this fork. Pre-Amsterdam these agree with the spec's parentheticals exactly. The EIP should express the cost as the fork's cold/warm access cost rather than fixed integers; reported upstream.
2. **`TXTRACE_GAS_COST = 100` is provisional** — the EIP's Constants table still marks it TBD; 100 is the EIP's own example value. It doubles as the flat cost of TXDIFF params `0x06`-`0x0A`.
3. **TXDIFF "after" reads the live state via the diff caches**, not a separately materialized post-tx snapshot. Inside a POST_TX frame the live `current_accounts_state` already reflects the executed body (POST_TX is the trailing suffix), so before (`initial`) vs after (`current`) is the whole-tx diff. The spec now confirms this reading directly ("If the queried key … was never modified during the transaction, TXDIFF returns the current live value for both the `before` and `after` variant"), so this is no longer flagged.
4. **Opcode bytes shifted one up: `0xB6`/`0xB7`/`0xB8` instead of the spec's `0xB5`/`0xB6`/`0xB7`.** EIP-8272's `RECENTROOTREFLOAD` already occupies `0xB5` on this branch (itself relocated from the spec's `0xB4`, which collides with EIP-8141's shipped `SIGPARAM`). Both EIPs are drafts assigning bytes in the same range, so one had to move; EIP-8272 keeps `0xB5` and EIP-7906 shifts up. Flag upstream so the two drafts settle non-overlapping bytes. See `docs/hegota-devnet.md`.

## ⚠ Remaining / flagged for devnet validation

- **A note on what this section used to say.** It previously described the revert semantics as underspecified and ethrex's exclude-the-transaction behaviour as spec-consistent, quoting the Security Considerations sentence "unconditionally invalidates the entire transaction, including any gas payment already approved". That was written against the pre-2026-07-06 draft, which said only that the prefix is "not reverted … in a mempool-compatible way" and nothing about inclusion or receipts. The 07-06 revision resolved all of it — inclusion, `status = 0`, prefix committed, payer charged, plus a rationale section named *Receipt Representation and Anti-DoS* — and the implementation is now aligned. **The quoted sentence still exists in the spec's Security Considerations and still contradicts the normative text; it predates the clarification and survived it.** Reported upstream as the likely cause of exactly this misimplementation.

- **Three sub-questions the partial revert genuinely leaves open** (none blocking, all consensus-relevant cross-client):
  1. **Gas on retroactively-unwound body frames.** EIP-8141 charges a *failed* frame its full `gas_limit`; a POST_TX revert unwinds frames that *succeeded*. We charge actual consumption, reading "the payer is fully charged for the gas consumed up to the point of the revert" literally, and do **not** rewrite body frame results to failure.
  2. **EIP-8037 state gas on a reverted body.** We drop it (`state_gas_used` rewinds to the body-entry value), mirroring the atomic-batch unroll on the same reasoning: the body was unrolled, so it grew no state. The alternative — charging state gas for state that no longer exists — is defensible too, and the EIP does not address 2D gas here.
  3. **Whether the remaining POST_TX frames in the suffix still execute** once one reverts. We stop at the first (the loop breaks). They are read-only so it cannot change state, but it changes gas, so it changes consensus.

- **EIP-8250 interplay inverted with the partial revert.** `consume_keyed_nonces` runs inside the APPROVE handler, i.e. in the validation prefix, so the keyed nonce is now **spent** on a POST_TX revert and the transaction is not replayable. Under the previous exclude-the-transaction behaviour it was rolled back, which is what made the DoS unbounded: the same transaction could be resubmitted indefinitely, costing a builder a full execution each time. Covered by `posttx_revert_consumes_the_keyed_nonce`. The spec's safety argument for committing the prefix ("the wallet controls the validation prefix, so it is inherently safe to commit it") is stated in EIP-8141 terms only, and does not obviously extend to what EIP-8250 / 8272 / 8037 write across that boundary — worth a ruling.

- **Receipts carry no assertion attribution.** A `status = 0` receipt says the transaction failed, not that a POST_TX assertion fired. Our choice to leave per-frame statuses as each frame's own outcome means the *frame* receipts do identify the failing assertion, but that is an ethrex property, not a spec guarantee.
- **CONFIRMED BUG (EIP-8141 frame-tx gas accounting, not EIP-7906) — needs a dedicated fix.** A storage write inside any frame is over-billed by the full EIP-8037 *state-gas* amount (~97,920 per `SSTORE_SET`). Root cause: `execute()` dispatches frame txs to `execute_frame_tx()` **before** `prepare_execution()`, so `add_intrinsic_gas()` never funds the per-tx `state_gas_reservoir` (stays 0); when a frame's SSTORE calls `increase_state_gas()`, the entire state portion **spills into `gas_remaining`** instead of being drawn from the reservoir, and the frame report hardcodes `state_gas_used: 0`. A normal tx draws the same state gas from the reservoir (2D split), so an identical SSTORE costs ~98k less outside a frame — a real divergence, and two cold SSTOREs already exhaust a 200k-gas frame. **Recommended fix (on `eip-8141-1`, not here):** fund a per-frame `state_gas_reservoir` from the frame's `gas_limit` headroom before `run_execution()` and reconcile it afterward (mirroring `add_intrinsic_gas` + `finalize_execution`), folding state gas into the report's `state_gas_used`. **First confirm with the spec/EELS whether frame txs participate in the EIP-8037 2D state-gas split at all** — the correct fix shape depends on it. Evidence: `vm.rs` (frame dispatch before prepare; reservoir init 0; `increase_state_gas` spill; `state_gas_used: 0`), `utils.rs` (`add_intrinsic_gas` — the only funder, never reached on the frame path). Until fixed, budget body/POST_TX frames generously.
- **`TXTRACE_GAS_COST`** finalization once the EIP freezes the value.
- Cross-client interop on the POST_TX trailing-suffix structural rule and the gating of the three opcodes outside POST_TX.
- **Deploying the TXDIFF repricing to a running devnet rewrites the gas of blocks already mined.** Blocks on `hegota-devnet` contain TXDIFF executions priced at the old flat cost, so after this change they no longer re-execute identically — a node syncing from genesis would compute a different receipts root. Needs either a fork boundary or an accepted re-sync break. The partial-revert change (gap 1) and the new params (gap 2) are history-safe by contrast: no POST_TX-reverting tx was ever included, and the new params previously halted.

## Tests

- **Pure functions** (`crates/vm/levm/src/opcode_handlers/tx_trace.rs`, `mod pure_fn_tests`): the diff views (`balance_changes`, `slot_changes`, `deployed_contracts`) — counts, before/after values, address/slot sorting, net-zero/restored/preexisting exclusions, EIP-7702 delegation exclusion; plus `address_slot_indices` / `address_event_indices` (local→global mapping, empty views, interleaved emission order) and `account_change_flags` (per-field bits, untouched address ⇒ 0, creation ⇒ all bits).
- **Integration** (`test/tests/levm/eip7906_tests.rs`): the opcodes through POST_TX frames using assert-or-revert (a succeeding tx means every assertion held). Covers TXTRACE inside POST_TX + gating (DEFAULT frame and normal tx halt), storage-change observation / gas payer + pre-charge / undefined-param + scalar-in2 halts, EVENTDATACOPY copy + gating, TXDIFF keyed params + unmodified-reads-live + scalar-in3 halt + gating, the per-address views and change flags (global-index cross-check against TXTRACE's table, out-of-range local index halts), and fork gating (opcodes invalid before Hegota).
- **Partial revert specifically**: `posttx_revert_rewinds_the_body_but_commits_the_prefix` (body write back to its prestate value *and* the payer still charged), `posttx_revert_drops_body_logs`, and `posttx_revert_fails_tx_without_invalidating_it`.
- **TXDIFF pricing**: `txdiff_state_params_are_priced_through_the_2929_access_lists` compares two byte-identical bytecode shapes whose second read is warm in one and cold in the other, so the gas gap isolates the TXDIFF charge and must equal the cold/warm delta — proving the access list is both consulted and updated. `txdiff_per_address_view_params_do_not_warm_the_access_lists` pins the converse for `0x06`-`0x0A`.
