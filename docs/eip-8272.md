# EIP-8272: Recent Roots for Frame Transactions

> **Spec target:** ethereum/EIPs `EIPS/eip-8272.md` @ commit `824cbc0b0e` (2026-09, PRs #12281 and #12302: the canonical recent-root verifier frame; Draft, Standards Track: Core; requires EIP-7623, EIP-7843, EIP-8141).

Implementation notes for EIP-8272 in ethrex. Builds on EIP-8141 frame transactions and EIP-7843 `SLOTNUM`; activates under `Fork::Hegota`.

## Overview

EIP-8272 lets a frame transaction prove that a set of **recent roots** — `(source_id, slot, root)` tuples — is committed in the `RECENT_ROOT_ADDRESS` predeploy, so validation code (a privacy proof, say) can bind to a recent commitment without reading third-party storage itself. Since `824cbc0b0e` the tuples travel in a **canonical VERIFY frame** to the predeploy rather than in an envelope field: the frame's data is one to sixteen packed 72-byte tuples, the frame runs the contract's validation operation under `STATICCALL` semantics, and a failing tuple reverts the frame, which invalidates the transaction. Applications read the frame back through EIP-8141's `FRAMEPARAM` / `FRAMEDATALOAD`; the EIP adds no opcode and no `TXPARAM` index.

## Implemented (this branch)

| Piece | Detail |
|-------|--------|
| Verifier frame | `Frame::is_recent_root_verifier`: `mode == VERIFY`, `target == 0x…8272`, `flags == 0`, `value == 0`, `limits.state == 0`, `72 ≤ len(data) ≤ 16 × 72`, `len(data) mod 72 == 0`. Anything else to that address is an ordinary frame. |
| Tuples | `RecentRootReference::from_tuple_bytes` over each 72-byte chunk (`source_id(32) ‖ uint64_be(slot) ‖ root(32)`); `FrameTransaction::recent_root_tuples`. |
| Mempool position | `FrameTransaction::recent_root_verifier_index`: frame 0, or frame 1 behind an expiry verifier. `validation_prefix` skips it like the expiry frame; `validate_prefix_structure` rejects a matching frame anywhere else (`RecentRootFrameMisplaced`) and counts the frame's `limits.execution` toward `MAX_VERIFY_GAS`. |
| Admission (`check_recent_root_frame`) | Before any EVM work, behind static validation and signature authentication: the predeploy must hold `RECENT_ROOT_CODE`, and every tuple must satisfy `slot < current_slot`, `current_slot − slot ≤ 8191`, and `storage[storage_key] == entry_hash`, with `current_slot = head.slotNumber + 1`. Each failure has its own `MempoolError`. |
| Simulation | The prefix simulation runs the frame's `RECENT_ROOT_CODE` with two permissions the observer grants only while that frame executes the predeploy at the top level: `SLOTNUM`, and `SLOAD` of the predeploy's own storage (`ValidationObserver::in_recent_root_frame`). The block context is `Blockchain::prospective_header`: head state, `slotNumber + 1`. |
| Revalidation | `revalidate_frame_txs_after_block` re-runs `check_recent_root_frame` for every pending frame transaction: a slot advance that ages a tuple out, or a reorg that uncommits it, evicts. |
| Profile 2 (EIP-8369) | `check_recent_root_frame_at_root` with the judged block's own slot, then the ordinary prefix replay, which grants the frame the same two permissions. |
| `RECENT_ROOT_ADDRESS` | predeploy at `0x…8272`, installed at activation (`install_recent_root_code`: create, or adopt an empty account keeping its balance, nonce `max(existing, 1)`). |

## `RECENT_ROOT_CODE`

The spec's constants table still reads `TBD`. ethrex installs a 345-byte runtime with both operations, selected by calldata length:

| Calldata | Operation |
|---|---|
| 64 bytes `salt ‖ root`, zero value | **write**: `storage[keccak(STORAGE_DOMAIN ‖ source_id ‖ be64(S mod 8192))] = keccak(ENTRY_DOMAIN ‖ source_id ‖ be64(S) ‖ root)` with `source_id = keccak(caller ‖ salt)`, `S = SLOTNUM`. Byte for byte the runtime of ethereum/sys-asm#53. |
| `n × 72` bytes, `1 ≤ n ≤ 16`, zero value | **validate**: for every tuple, `slot < SLOTNUM`, `SLOTNUM − slot ≤ 8191`, and the stored entry equals the tuple's entry hash; any failure reverts, success returns nothing and changes nothing. |
| anything else, or value | revert |

| | |
|---|---|
| Length | 345 bytes |
| `keccak256(RECENT_ROOT_CODE)` | `0xcd1cae00e1d37cf97195f9e716dfa1b9a804e36bb5d7726c4f2c50e2580275a5` |
| `PUSH32 ENTRY_DOMAIN` | at `0x28` (validate) and `0xeb` (write) |
| `PUSH32 STORAGE_DOMAIN` | at `0x4c` (validate) and `0x123` (write) |
| Source | `scripts/hegota-testnet/recent_root/main.eas` (geas, `-a -no-stackcheck`); a reference-vector and case check in `mini_evm.py` |

The validation operation is ethrex's implementation of the spec's prose and is recorded as a divergence until upstream publishes bytes; the hash layout is unchanged from the write-only runtime, so roots written under the old code stay readable. The ring index is `slot AND 0x1fff`, correct only while `RECENT_ROOT_LENGTH` is 8192, and the age compare uses `0x1fff` as `RECENT_ROOT_USABLE_WINDOW`; compile-time assertions pin both constants.

## Divergences from the spec

1. **`RECENT_ROOT_CODE` bytes are ethrex's** (above). Everything the frame observes — hash layout, window, tuple encoding, revert-on-failure — follows the spec text.
2. **Beacon slot source: EL-derived when the CL does not forward it (EIP-7843 dependency).** `env.slot_number`, which both operations and the mempool window key on, is meant to come from the consensus layer over the engine API. The `derivedSlotTime` knob lets a single-EL devnet derive it from the timestamp; the testnet leaves it unset and takes the CL's slot.
3. **Dependency tracking is a full rescan.** The spec asks clients to index pending transactions by `(storage_key, entry_hash)` and expiry slot; ethrex re-checks every pending frame transaction after every block (`revalidate_frame_txs_after_block`), which satisfies the rechecking rule at the cost of work proportional to the pending frame transactions, bounded by one per sender.

## Removed with `824cbc0b0e`

The envelope field `recent_root_references`, its RLP and signature-hash coverage, the per-reference intrinsic gas, `TXPARAM 0x11`, the `RECENTROOTREFLOAD` opcode, and the pre-execution reference check in `execute_frame_tx`. The type-0x06 envelope is back to eight fields; the golden vector in `frame_tx_wire_tests.rs` and `scripts/hegota-testnet/frametx.py` pins it.
