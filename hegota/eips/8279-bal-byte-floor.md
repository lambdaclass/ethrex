# EIP-8279: Block Access List Byte Floor
- **Layer:** EL
- **EIP status:** Draft
- **Hegota status:** Proposed (CFI) — acde/238, 2026-06-04
- **Authors:** Toni Wahrstätter
- **Links:** [spec](https://eips.ethereum.org/EIPS/eip-8279) · [discussion](https://ethereum-magicians.org/t/eip-8279-block-access-list-byte-floor/28662)
- **Prior fork history:** none recorded

## TL;DR
EIP-7928 Block Access Lists (Glamsterdam) add a new source of block bytes that no floor prices: an attacker can pack ~1.55 MB into a 60M-gas block via cheap cold SLOADs (32 BAL bytes per 2,100 gas) plus calldata. This EIP meters every byte an opcode contributes to the BAL in a per-transaction counter and folds it at 64 gas/byte into the EIP-7623/8131 floor, capping worst-case block content at `block_gas_limit / 64` ≈ 0.89 MB — a ~42% cut. Typical transactions are unaffected; the runtime floor never binds on its own.

## What it changes
- Two internal per-transaction counters (not in the tx format, not persisted): `bal_data_bytes` (bytes this tx contributes to the BAL) and `floor_gas_used = static_floor + bal_data_bytes * 64`.
- `meter_bal_data(n)` is called *before* each BAL-growing operation: cold account access (+20), cold storage access (+32), first SSTORE moving a slot off its pre-tx value (+32, refunded if restored), value-bearing CALL / SELFDESTRUCT sweep (+32), CREATE/CREATE2 nonce (+8) and endowment (+32), deployed code (+len). If the new floor exceeds `tx.gas`, raise OOG before the BAL entry exists.
- Static seed = EIP-8131's `tx_floor` + 51 BAL bytes per EIP-7702 authorization (authority address + delegation marker + nonce), because `set_delegation` runs outside the EVM OOG handler.
- Final charge unchanged in shape: `tx.gasUsed = max(execution_gas_used, floor_gas_used)`; validation requires `tx.gas >= max(intrinsic, static_floor)`.
- The meter is a deliberate upper bound: reverted frames' metered bytes are never rewound (BAL keeps accesses across reverts anyway). The only refund is the storage-value byte when a slot returns to its pre-tx value (BAL no-op write), keyed to the BAL rule — not to the SSTORE gas refund.
- System-contract calls (EIP-2935/4788/7002/7251) and withdrawals are exempt; covered by EIP-7928's block-level item buffer.

## Motivation
Nodes must handle the worst block an attacker can build. EIP-7623 priced calldata, EIP-7981 access lists, EIP-8131 all tx-content fields — but none price BAL bytes, which are generated by runtime opcodes. The calldata + cold-SLOAD bypass pushes intrinsic gas above the calldata floor and then loads the block with cheap BAL entries. One flat 64 gas/byte rate makes the worst case invariant to the attacker's chosen vector, buying headroom for gas-limit increases or pure robustness.

## Dependencies & related EIPs
- **Depends on:** EIP-7928 (BALs, Glamsterdam) and EIP-8131 (uniform tx-content floor, Hegota candidate) — this EIP reuses 8131's floor and explicitly does not work standalone ("Neither EIP alone closes the bypass"). Also references EIP-7623, EIP-7976, EIP-7981, EIP-7702.
- **Interacts with:** EIP-8358 (net account metering) and EIP-3298 (refund removal) — both change the refund/revert semantics that 8279's meter deliberately stays independent of; ordering of these changes should be kept clean. EIP-8374 (persist warm sets across reverts) is philosophically aligned with 8279's never-rewind meter.
- **Cluster context:** the BAL byte-floor entry of the gas repricing cluster.

## Impact on ethrex / client teams
- Medium. Requires a metering hook at every BAL-contributing opcode in LEVM (`crates/vm/levm/src/opcode_handlers/`), the per-tx counters in the execution environment, and coordination with the BAL builder (`crates/common/types/block_access_list.rs`, `crates/blockchain/`).
- Tx validation changes (floor in `tx.gas` minimum) touch the tx pool and `eth_estimateGas`, which must simulate runtime metering — wallets will lean on this heavily.
- No new tx fields, no networking/Engine API changes. Deterministic OOG-before-insertion ordering is the main consensus-correctness risk.

## Open questions & controversies
- Adds 0.54 pp more transactions paying more (+0.77 pp gas) on top of EIP-8131's 3.24%/+3.29% (mainnet sample, May 2026) — small but nonzero user impact for a purely defensive bound.
- Gas estimation complexity: wallets must simulate runtime BAL metering, not just intrinsic gas; underestimation leads to validation rejections.
- Deliberate over-counting (no rewind on revert) is safe but means the meter and the actual BAL diverge — fine for a floor, but a subtle invariant to maintain if the BAL spec changes.
- Coupled fate with EIP-8131: if 8131 slips, 8279 has nothing to hook into.
